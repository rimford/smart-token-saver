Why it exists

Every message you send in Claude Code sends the whole chat again. While the prompt cache is warm, that costs little: Opus 5.5 reads the history at 5 % of the normal price. After a pause the cache goes cold (one hour on a subscription, five minutes on API credits), and the next message pays full price for everything.

So long chats and pauses are where the money goes. Smart Token Saver helps in three ways:

  • It picks the effort per message, so a quick question doesn't run as deep as a refactor.
  • It shows how full the chat is and how long the cache stays warm.
  • It compacts or hands off in one click, and picks the cheaper way when the chat is cold.

Install

Paste this into any Claude Code chat and press Enter:

/plugin install smarttokensaver --marketplace rimford/smart-token-saver

On an older Claude Code, add the marketplace first with /plugin marketplace add rimford/smart-token-saver, then /plugin install smarttokensaver@smart-token-saver. In the desktop app, + → Plugins → Add marketplace takes rimford/smart-token-saver as well.

It needs a current Claude Code (tested with 2.1.330). If no bar shows up in the new chat, /plugin says why the plugin did not load; most often Claude Code is too old.

Then open a new chat. That's it. Plugins load when a chat starts, so the chat you installed from doesn't show the bar yet.

In the new chat a short setup opens above the prompt. After a welcome page it asks three questions, each with a line that explains every option: how much Smart should lean cheaper or smarter (Balanced is recommended), which compaction window to use (300k is recommended) and whether the panels follow the app or are always dark or light. Nothing is saved before Finish; a green Setup complete then sums up what was set. If effortless (the public plugin Smart Token Saver is based on) or a second copy of Smart Token Saver is installed, the setup offers to remove it. Run the setup again any time with /smarttokensaver setup.

Smart effort

With Smart on, Haiku 5.5 reads each message before it goes out and picks Low, Medium or High. "What does this function do?" gets Low. "Find why the totals are off across these three jobs" gets High. It takes about a second and uses your own Claude login.

Smart stops at High. The two levels above it cost a lot more and rarely help in everyday work. You can change the range in Settings.

Smart runs on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.2. On these models the effort can change from one message to the next without losing the prompt cache: measured on each of the four, 99 to 100 % of the chat was still read from the cache after a change. On older models (Fable 5.1, Opus 5 and earlier) a change makes the next message reread most of the chat at full price, so Smart pauses there and the bar says Smart paused.

A level you name in your message ("use max effort for this") is taken as said.

On Default, every message runs at the effort you set in the app. If you change the effort yourself, the switch goes to Default at your next message and tells you. Your choice always wins.

Not proven yet: whether Smart effort saves money is still open. The first measurements are too few. See What's proven.

Cold chats

When the countdown runs out on a big chat, the bar turns light blue:

✦ Chat went coldRereads 210k tokens at full price.Handoff

It shows from about 110k to 150k tokens, depending on your compaction window (30k below the compaction point, but never below 110k or above 150k). Smaller chats are cheap enough to reread.

You can carry on, compact or hand off. The next section compares them.

Running low and Save mode

Your Claude plan has two usage limits: one for the last 5 hours and one for the week. Once either passes 80 %, an orange band shows above the prompt:

✦ Running low80% of your weekly limit used · resets Tue 08:00Save modeSkip for nowSkip this week

It names the fuller of the two limits and when it resets. Its second line has the reset time, a link here and one to the switch in Settings → Effort.

Save mode stretches what's left. While it's on, Smart effort picks at most Medium. A message Smart would have sent at High goes at Medium; Low and Medium stay as they are. High thinks longer and writes more, and that's what eats the limit fastest, so capping it gives you noticeably more messages before you hit the wall. Everyday questions don't change at all.

  • Turn it on with Save mode in the band (s in the terminal), with the Save mode switch in Settings → Effort (there at any time, also before a limit runs low), or with /smarttokensaver save. The button then reads Save mode on.
  • It ends by itself when the limit resets, the 5-hour one or the weekly one, whichever the band showed. Turned on in Settings while no limit runs low, it lasts 5 hours. Press the button or the switch again to turn it off earlier. It holds in the chat where you turned it on.
  • It only touches Smart effort. If you set the effort yourself, or the switch is on Default, your choice wins as always. Model, compaction window and everything else stay as they are, and no message is held back.
  • Skip for now hides the band until the limit is 5 points fuller: skipped at 80 %, it comes back at 85 %, then 90 % and 95 %.
  • Skip this week hides it until the weekly limit resets (for the 5-hour limit the button reads Skip until reset). The next limit that runs low shows it again. The Running low alert itself can be turned off in Settings → Handoff & alerts.

When to use it: a long task should still finish before the reset, or you want to keep some room for later in the week. When not to: you're in the middle of something hard where High matters more than the limit. Then leave it off and maybe hand off to a fresh chat instead, which saves more anyway (see Compact, Handoff or carry on).

Compact, Handoff or carry on

Carry onYour next message rereads the whole chat once at full price. After that it's cheap again until the next pause.
Same taskCompactClaude replaces the chat with a summary. You stay in the same chat and keep going.
Next taskHandoffClaude writes a short note, clears the chat and starts fresh with the note as the first message.

What each costs

Example: a cold chat with 210k tokens on Opus 5.5, at list prices. On a subscription the same ratios apply to your usage limit.

OptionOncePer message afterChat size after
Carry on$1.05 to $1.70$0.04210k and growing
Compact, cold (Haiku 5.5 writes it)$0.13$0.0120k to 50k
Compact with the chat's model$1.00$0.0120k to 50k
Handoff, Quick (Haiku 5.5 writes it)$0.11$0.002about 10k

Prices: Opus 5.5 $4 per million input tokens, $0.20 when cached, $20 output. Haiku 5.5 $0.50 input and $2.50 output above 100k tokens.

Over ten more messages, carrying on costs about $1.20 to $1.90 more than compacting or handing off. Between Compact and Handoff the difference is a cent or less per message.

Which to pick

  • Same task, and the details matter (numbers, decisions, what you tried): Compact. You can add a note on what the summary must keep, like "keep the test results and the open question about the date filter".
  • One part is done and a new one starts: Handoff. The new chat is small and isn't distracted by old history.
  • You're finished: do nothing. A chat you don't touch costs nothing.

Who writes the summary

Settings → Model → Summaries. Auto (default) uses Haiku 5.5 when the cache is cold (about $0.13 instead of $1 for 210k) and the chat's own model when it's warm, where it reads the chat cheaply and writes the better summary. Chat's model always uses the chat's model. If Haiku 5.5 fails, the chat's model takes over.

Haiku 5.5 sees long tool output shortened, so its summary has less detail. If a chat is full of details you need, use Handoff, or switch to Chat's model for that one compaction.

Handoff options

The Handoff button opens a bar with two choices: who writes the note, and what happens next. A few dim words beside them say what the picked kind is, and a line under them says what the picked way on does. On the left, Compact instead switches to the compact bar. The bar remembers your last choice.

Quick or Full

RecommendedQuickWritten in seconds from the chat, without tools. On a cold chat Haiku 5.5 writes it. The git state in it is what the chat last saw.
FullA normal turn with tools. It checks git, commits and pull requests (asking GitHub when the gh tool is installed), rewrites HANDOFF.md in your project and then answers with the note. Slower, costs a full turn, and leaves a file in your repo.

Use Full before a longer break or when the exact git state matters. In Settings you can point Full at your own handoff skill.

What happens next

RecommendedClear & waitThe chat is cleared. The new chat sums up in two lines where things stand and waits. You check the note before anything runs.
Clear & carry onThe chat is cleared and the new chat starts on the next step right away. Faster, but it works from a note you haven't read.
Keep chat & copyNothing is cleared. The note goes to your clipboard, for a new chat somewhere else or to keep the old one.

The plugin never overwrites a draft in your prompt box. If a note can go neither into the new chat nor to the clipboard, it is kept, and /smarttokensaver handoff note shows it.

The compaction window

Opus 5.5 and Fable 5.2 can hold one million tokens, and by default Claude Code lets a chat grow to almost that before it compacts. Every message rereads the whole chat: a chat at 800k pays for 800k tokens on every message, even for a short follow-up. A limit on the chat's size (the compaction window) is the plugin's biggest saving. The default is 300k; such a chat compacts at about 267k.

What a limit saves

Seven weeks of one heavy user's real chats, replayed message by message under different limits, at list price:

WindowCost vs. no limit (1M)Cost vs. 400kCompactions per week
200k−32 %−13 %131
300k (recommended)−30 %−9 %40
400k−23 %±020
600k−12 %+14 %9
No limit (1M)±0+29 %4

The saving comes only from chats that grow past the limit. If you mostly ask short questions in fresh chats, expect little. If you work in long sessions, expect those sessions to cost about half; across everything, about a third less than without a limit.

Why 300k and not less: below 300k the saving flattens (250k saves only 3 % more), while compactions keep doubling, and each one takes about a minute and a half and drops detail from the chat. The full measurement, with what is not known yet, is in the documentation.

Changing it

  • Settings → Context size → New chats, or /smarttokensaver window 350k for any value from 100k to 1M. Claude Code default leaves the limit to Claude Code.
  • If your organization sets a limit, it wins, and the card says so.

Context size for one chat

Sometimes a chat is worth keeping whole: a long debugging session, a big review, a plan you are halfway through. Give that one chat a bigger limit while your default stays as it is:

  • Settings → Context size → This chat only: pick a size, or Your default to go back.
  • Near compaction, the "Chat window is getting swamped" warning offers the same choice as Context size, next to Handoff and Compact.
  • Or type /smarttokensaver window this 500k, and /smarttokensaver window this reset to undo it.

The card says asked until Claude Code confirms the size, then in use. A bigger window isn't free: every message reads the whole chat. Use it when losing detail would hurt more than the extra cost.

Everything that depends on the limit adjusts itself: the ring, the cold bar, the "getting swamped" warning (from 227k at 300k, from 507k at 1M) and the handoff check.

When the plugin can't set it

Some organizations don't let plugins change Claude Code settings. The plugin notices that, says so at the top of the Context size card and in the setup, and offers the way that works:

  • New chats: the size is saved in ~/.claude/settings.json (autoCompactWindow), and the plugin tells you so. The file as it was is kept beside it as a backup.
  • This chat: the card shows /autocompact with the size, with Paste into chat and Copy. Nothing goes into the chat by itself: you send the command.
  • If the settings file is closed too: Paste into new chat opens a new chat with a request to write the size into the file, for you to send and allow.

Every step of this is described in the documentation.

Settings

Open Settings with ⚙ in the bar or under the prompt, or with /smarttokensaver settings. The overview shows one card per part, each with a short line on what is set. Click a card to open it; ← Settings top left goes back. Every change saves itself the moment you make it; ✓ Saved shows top right for a moment, and the change reaches every open chat within a few seconds. Each open card has one row per setting: its name, the control, and a short line on what it does. The Guide button top right, next to ✕, opens the matching section of this page.

Effort

The overview line says the lean and the limits, for example Balanced · low to high.

LeanFive stops from Cheapest to Smartest. Balanced (recommended) lets Haiku 5.5 decide alone. Cheaper and Smarter only tip close calls, when Haiku is torn between two levels; Cheapest and Smartest move more messages down or up.
LimitsMin and Max: the lowest and highest level Smart may pick (default Low to High).
SubagentsOff by default: subagents run at the chat's effort. On, Smart reads each subagent's task first and picks its effort, Medium or more.
Save modeKeeps Smart at Medium or below until the usage limit resets. The Running low band offers the same switch (see Save mode).

Commands: /smarttokensaver auto switches Smart on and off, /smarttokensaver save switches Save mode, /smarttokensaver stats sums up the efforts of this chat.

Model

The overview line says whether the chat keeps its model.

Simple promptsAlways the chat's (default): every message keeps your model, only the effort changes. Cheaper when it can lets Haiku 5.5 or Sonnet 5.5 answer simple messages. It is marked experimental because it rarely saves anything yet: the prompt cache belongs to one model, so the other model reads the whole chat again at full price, which often costs more than the cheaper model saves. It only pays on short chats or after a long pause, when the cache is cold anyway, and the answer can differ in style from your model's. It is kept to measure it, not as a recommendation.
SummariesWho writes the summary when a chat compacts. Auto: Haiku 5.5 on a cold cache, the chat's model on a warm one, whichever is cheaper. Chat's model: always the chat's model. Where your organisation keeps plugins out of compaction, a note says the chat's model writes every summary.

Handoff & alerts

The overview line says who writes a Full handoff and when the context alert comes, for example Built in · alert at Auto.

Handoff skillWho writes a Full handoff: Smart Token Saver's own (built in), or one of your installed skills or commands (see Handoff options).
Handoff buttonWhen advised (default): the bar's button turns into Handoff only when Haiku 5.5 thinks a fresh chat beats compacting. Always: Compact and Handoff sit side by side in the bar as two quiet buttons; each opens its own bar, and each bar can switch to the other. Handoff only lights up once Haiku 5.5 advises it.
AlertsWhich bands show above the prompt. Context: the chat is nearly full, at Auto (recommended, see the compaction window) or a fixed percent. Running low: a usage limit is close. Cold cache: the next message pays full price. An alert's ✕ only closes it for now; the box here switches it off.

Commands: /smarttokensaver handoff writes a quick handoff at once with your last choice, /smarttokensaver handoff full a full one.

Privacy

  • Picking the effort, checking for a handoff and Haiku 5.5 summaries go through the same connection Claude Code uses, with your own Claude login. No extra service sees your prompts. If your Claude Code runs through a gateway, these calls do too.
  • The only network call of its own is the update check against this plugin's GitHub repository, done by Claude Code's own claude plugin marketplace update. Turn off in Settings → Support stops it. /smarttokensaver guide opens this page in your browser when you ask.
  • Where Claude Code does not let the plugin set the compaction window directly, setting it (Setup, the Context size card) writes it into ~/.claude/settings.json; the file as it was is kept beside it (settings.json.smarttokensaver.bak, and the two copies before it). That value stays after an uninstall until you remove autoCompactWindow from the file.
  • No usage log and no analytics. The plugin keeps its own settings under ~/.claude/smarttokensaver/; a Full handoff saves HANDOFF.md in your project.

The public effortless plugin can send prompts to an outside judge service. Smart Token Saver removes that.

Updates

Settings → Support → Updates checks rimford/smart-token-saver every six hours, the same way Claude Code updates any marketplace. When a newer version is out, a card above the prompt offers Update, Later or Skip. Update installs it for every new chat; the chat you are in keeps the old version unless you reload it (a message says how). Claude Code's own marketplace auto-update works too, if you switch it on for this marketplace.

Found a bug? Settings → Support → Report a bug, or /smarttokensaver support for the link.

What's proven

  • The compaction window saves money. The replay above holds up for heavy use.
  • Compacting or handing off a cold chat saves money. That follows from the prices.
  • Whether Smart effort saves money is open. The first measurements are too few and point both ways.
